# GENESIS — продуктовая идея и техническая цель

## Кратко
GENESIS (Embodied Learning Lab) — интерактивная локальная лаборатория воплощённого обучения. В физической симуляции MuJoCo двуногое тело учится управлять собственными суставами через взаимодействие со средой. PPO оптимизирует нейросетевую управляющую политику. Пользователь наблюдает одновременно тело, обучение и ту же нейросеть, которая непосредственно управляет телом.

Это не заранее подготовленная анимация: движение должно быть следствием действий policy и расчёта физики. Каждый вывод о прогрессе подтверждается логами и метриками.

## Главная идея интерфейса
На экране одновременно видны:
- физическое тело в симуляции, его поза, суставы, контакты и падения;
- нейросеть управления с настоящими активациями, весами и выходными командами;
- состояние обучения, число шагов и метрики качества поведения;
- понятное объяснение текущего эксперимента.

Визуализация не должна подменять реальную модель. Никаких декоративных нейронов и заранее записанных движений. Если данных нет, интерфейс честно показывает ожидание/отсутствие телеметрии.

## Цель обучения
Первая цель — базовый моторный контроль: восстановление/удержание вертикального положения (stand/recovery). После измеримого успеха и повторяемости:
1. баланс в разных начальных положениях;
2. восстановление после контролируемых возмущений;
3. первые шаги;
4. устойчивая ходьба;
5. бег.

Текущий код содержит обозначения задач `stand`, `walk`, `run`, но наличие параметра task не является доказательством освоенного навыка. UI сейчас запускает `stand`. Все новые задачи требуют отдельных экспериментов и критериев успеха.

## Научно-технические принципы
1. Физика прежде анимации: суставы, контакты, силы и падения рассчитываются MuJoCo.
2. Реальная политика: действия тела создаёт та PPO actor policy, чьи активации и веса показываются.
3. Обучение с нуля: не использовать motion-capture/готовую походку как подмену обучения базового этапа.
4. Проверяемость: оценивать поведение через измеримые метрики, несколько seed и baseline.
5. Разделять PPO и нейроэволюцию: PPO меняет параметры фиксированной архитектуры; эволюция топологии — отдельная будущая исследовательская задача.
6. Не антропоморфизировать вычисления: нейронные активации не означают сознание, мысли или понимание.

## Технический стек
- MuJoCo — физическое тело.
- Gymnasium — RL environment.
- PyTorch + Stable-Baselines3 PPO — обучение.
- FastAPI + WebSocket — API и телеметрия.
- React + TypeScript + Vite + Canvas 2D — интерфейс.

## Критерии качества
- Тело физически симулируется и напрямую управляется действиями policy.
- Наблюдения и действия имеют согласованные размерности и конечные значения.
- Reward отражает целевой моторный навык, а не случайную активность.
- Обучение демонстрирует улучшение относительно baseline на нескольких seed.
- В UI отображаются данные именно той модели, которая управляет телом.
- Состояния disconnected/starting/training/completed/error обрабатываются честно.
- Запуск и проверки воспроизводимы на Windows и Linux.
- Ошибки, ограничения и непроверенные гипотезы документируются.

## Не является целью
- Обещать искусственное сознание или человеческий интеллект.
- Рисовать красивую, но не связанную с физикой анимацию.
- Объявлять walk/run освоенными по факту наличия соответствующего кода.
- Усложнять интерфейс десятками графиков до работающего базового цикла.
- Переписывать проект целиком ради косметики.
