# Дорожная карта LIFE ENGINE

Обновлено: 2026-10-29. Приоритет изменён по обратной связи игрока: проект должен стать игрой, а не просто красивым экраном с микроорганизмами. Не изображать цивилизации декорацией — добавлять их только вместе с причинными механиками.

## P0 — игровой цикл и производительность
- [ ] Проверить в браузере, что крупные события среды видны в HUD и журнале, действительно меняют условия и не ломают сохранения.
- [ ] Проверить лаги до/после ограничения Canvas до 30 FPS; замерить поведение при большой популяции и ×50.
- [ ] Добавить понятную цель текущего мира и последствия решений игрока: игрок должен знать, за чем наблюдать и зачем вмешиваться.
- [ ] Провести browser smoke-test: запуск/пауза, скорость, события, сохранение/загрузка, импорт/экспорт.

## P1 — непредсказуемая история мира
- [x] Добавить первые глобальные события: цветение, голодная полоса и смена течений; каждое событие временно меняет модель и определяется seed.
- [ ] Проверить баланс событий на нескольких seed и горизонте 100–300 поколений: частота, длительность, вымирания и восстановление.
- [x] Добавить события о крупных изменениях численности линий с фактическими числами и осторожной формулировкой причин.\n- [ ] Углубить причинный анализ: проверить связь выигрыша/потерь с конкретными признаками и режимом среды на нескольких seed.
- [ ] Сделать журнал мира полноценной хроникой важных поворотов, сохраняя сигнал/шум и ограничивая повторяющиеся уведомления.

## P2 — эволюция в полноценную игру
- [ ] Разработать этапы развития мира: микробы → сложные организмы → разум/общество → цивилизации → технологии и космос. Переходы должны открываться из состояния мира, а не по таймеру и не как декоративная наклейка.
- [ ] Добавить долгосрочные цели и решения игрока, влияющие на ход истории.
- [ ] Сделать возвращение после долгого отсутствия осмысленным: краткая сводка «что произошло, кто изменился, какие угрозы появились».
- [ ] Развести масштабы симуляции, чтобы развитие цивилизаций не требовало рисовать тысячи отдельных организмов.

## P3 — качество и устойчивость
- [ ] Проверить нулевую популяцию, пустые ресурсы, предел численности, ошибочный импорт и миграцию сохранений.
- [ ] Измерить FPS и длительность шага при обычной и максимальной популяции.
- [ ] Проверить рост памяти и истории при длительном прогоне.
- [x] Сохранять и проверять причинные правила симуляции автоматическими тестами.

Пункт считается завершённым только после конкретной проверки с результатом в `docs/TESTING.md`. Написанный код сам по себе не является доказательством работоспособности.
