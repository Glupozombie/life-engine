# Дорожная карта

Приоритеты — предварительные. После аудита кода пересортировать задачи по реальному состоянию и стоимости изменений.

## Этап 0 — аудит и воспроизводимый запуск
- [ ] Зафиксировать структуру файлов, стек, версии и команды запуска.
- [ ] Установить, как запускаются симуляция и тесты.
- [ ] Проверить текущую сборку и консоль браузера.
- [ ] Найти реальные места в коде, отвечающие за организмы, физику/движение, ресурсы, мутации и сохранения.
- [ ] Составить список ошибок и неработающих функций.
- [ ] Обновить `docs/CURRENT_STATE.md` и `docs/ARCHITECTURE.md`.

**Готово, когда:** другой разработчик может запустить проект по инструкции, а состояние основных функций подтверждено.

## Этап 1 — визуальная читаемость
- [ ] Сделать организмы различимыми по форме и силуэту, не только по цвету.
- [ ] Связать визуальные признаки с параметрами организма.
- [ ] Улучшить читаемость ресурсов, опасностей и важных взаимодействий.
- [ ] Добавить обратную связь для важных действий: питание, столкновение, размножение, мутация и смерть.
- [ ] Сократить шум интерфейса; оставить симуляцию главным элементом.
- [ ] Проверить производительность при обычной и высокой численности популяции.

**Готово, когда:** игрок может глазами отличать несколько типов организмов и замечать значимые действия без чтения графиков.

## Этап 2 — работающий эволюционный цикл
- [ ] Проверить и документировать правила потребления ресурсов и энергетического баланса.
- [ ] Проверить размножение, наследование и стоимость размножения.
- [ ] Убедиться, что мутации изменяют реальные наследуемые параметры.
- [ ] Убедиться, что наследуемые параметры влияют на успех организмов.
- [ ] Проверить смерть, вымирание и пустую популяцию.
- [ ] Добавить контролируемые условия среды, если это соответствует архитектуре.
- [ ] Создать повторяемые сценарии для проверки причинно-следственных связей.

**Готово, когда:** можно объяснить, почему определённая линия стала чаще встречаться или исчезла, исходя из правил модели.

## Этап 3 — журнал событий и дерево происхождения
- [ ] Добавить/исправить понятный журнал значимых событий.
- [ ] В сообщениях показывать причину и результат, а не только техническое имя события.
- [ ] Отслеживать родителей, потомков и происхождение линий.
- [ ] Отображать ветвление, распространение и исчезновение линий.
- [ ] Связать выбранный организм с его линией и событиями.
- [ ] Ограничить объём истории, чтобы не допускать неограниченного роста памяти.

**Готово, когда:** игрок может проследить историю конкретной линии и понять, что с ней происходило.

## Этап 4 — интерфейс для обычного игрока
- [ ] Основные элементы: старт/пауза, скорость, популяция, ресурсы.
- [ ] Понятные подсказки для новичка.
- [ ] Карточка выбранного организма с объяснением признаков простым языком.
- [ ] Краткие итоги за выбранный промежуток времени.
- [ ] Сложные графики и параметры — в сворачиваемой лаборатории.
- [ ] Пустые состояния и ошибки объясняются человеку, а не только в консоли.

**Готово, когда:** основные функции понятны без специальных знаний.

## Этап 5 — сохранения и возвращение к миру
- [ ] Проверить существующую систему сохранений.
- [ ] Сохранять необходимые данные мира, популяции, линий происхождения и настроек.
- [ ] Проверить загрузку после закрытия и повторного открытия браузера.
- [ ] Обработать повреждённые, устаревшие и несовместимые сохранения.
- [ ] При необходимости добавить слоты, экспорт и импорт.
- [ ] Спроектировать ограниченный офлайн-прогресс или пакетный расчёт прошедшего времени.
- [ ] Проверить миграцию формата сохранений при обновлении игры.

**Готово, когда:** сохранённый мир надёжно восстанавливается и не получает фиктивный прогресс.

## Этап 6 — полировка и устойчивость
- [ ] Проверить долгую работу и рост использования памяти.
- [ ] Проверить большие популяции и ускорение времени.
- [ ] Проверить поведение при нулевых ресурсах и вымирании.
- [ ] Проверить восстановление после ошибок сохранения.
- [ ] Обновить README с командами установки, запуска, проверки и сборки.
- [ ] Подготовить демонстрационный сценарий для первого запуска.

## Правило изменения приоритетов
Не выполнять этапы механически. Если аудит покажет, что часть уже работает, проверить её и перейти дальше. Если крупная функция нестабильна, исправить её до добавления новых функций. Один этап может быть разбит на небольшие проверяемые задачи.
