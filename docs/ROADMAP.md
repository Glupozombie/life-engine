# Дорожная карта GENESIS

Порядок основан на рисках и зависимостях. Не переходить к следующей фазе, пока критерии предыдущей не подтверждены.

## P0 — воспроизводимый запуск
- [ ] Исправить `npm run dev/build`: npm scripts не находят локальные `vite`/`tsc`, хотя прямые `.cmd` запускаются.
- [ ] Выяснить причину пустой страницы Firefox по Console и Network.
- [ ] Подтвердить запуск backend и frontend одновременно.
- [ ] Проверить WebSocket соединение и реальные snapshot.
- [ ] Сверить локальный checkout с актуальным `main`.

## P1 — валидировать физическую среду
- [ ] Добавить/проверить smoke test загрузки MuJoCo XML.
- [ ] Проверить observation/action shapes, dtype, finite values и Gymnasium API.
- [ ] Запустить random policy на серии эпизодов; собрать падения, reward, termination и NaN.
- [ ] Проверить контакты ног, геометрию, масштаб, суставные ограничения и начальные позы.
- [ ] Разложить reward на компоненты и проверить, что нет очевидных loopholes.

## P2 — измерить обучение stand/recovery
- [ ] Получить baseline random/no-op policy.
- [ ] Выполнить короткие PPO прогоны с фиксированными seeds.
- [ ] Логировать episode length, upright duration, fall rate, reward components и скорость.
- [ ] Сравнить несколько seeds, сохранить конфигурации и checkpoints.
- [ ] Зафиксировать критерии успеха stand до настройки гиперпараметров.
- [ ] Устранить нестабильность/NaN и доказать улучшение относительно baseline.

## P3 — надёжность backend и UI
- [ ] Проверить lifecycle обучения, повторный запуск и stop.
- [ ] Гарантировать закрытие env при исключениях.
- [ ] Проверить WebSocket reconnect и поведение при backend error.
- [ ] Проверить согласованность snapshot, body coordinates и Canvas scaling.
- [ ] Проверить, что weights/activations относятся к текущей actor policy.
- [ ] Добавить понятные сообщения об ошибках и статусах.

## P4 — воспроизводимость и удобство экспериментов
- [ ] Надёжное сохранение/загрузка и resume PPO checkpoints.
- [ ] Хранение seed, hyperparameters, версии кода и результатов запуска.
- [ ] Сравнение нескольких policy/checkpoints.
- [ ] TensorBoard или компактный experiment report.
- [ ] Документированный end-to-end сценарий запуска.

## P5 — расширение моторных навыков
- [ ] Curriculum для разных стартовых поз и восстановления после возмущений.
- [ ] Первые шаги и отдельные критерии ходьбы.
- [ ] Устойчивая ходьба на нескольких seeds.
- [ ] Бег только после воспроизводимой ходьбы.

## P6 — нейроэволюция (отдельное исследование)
- [ ] Определить формат генома и совместимость с наблюдениями/действиями.
- [ ] Реализовать topology mutation, speciation и selection.
- [ ] Сравнить с PPO baseline на одной и той же задаче.
- [ ] Визуализировать только реальные узлы/связи текущей policy.

## Критерии перехода
Нельзя помечать этап завершённым по наличию кода. Нужны воспроизводимые проверки, метрики, зафиксированные seeds/configuration и честное описание ограничений.
