## Фактический стек

- HTML, CSS и JavaScript ES modules без UI-фреймворка.
- Canvas 2D для мира и аналитических графиков.
- IndexedDB для сохранений с fallback через localStorage.
- `package.json` содержит `"type": "module"`; внешних npm-зависимостей и scripts в нём нет.
- `tests/simulation.test.js` содержит 15 проверок ядра, причинных сценариев и хроники эволюционных линий на встроенных `node:test` и `node:assert`.
- `scripts/evolution-experiment.js` сравнивает одинаковый начальный мир при фиксированном seed в трёх режимах среды и печатает JSON-траекторию поколений.
- `.github/workflows/validate-archive.yml` настраивается для проверки исходников в Git, автоматических тестов и сохранённого ZIP.

## Запуск

Из корня репозитория:

```bash
python -m http.server 8000
```

Затем открыть `http://localhost:8000`. Запуск через `file://` не поддерживается из-за ES modules и IndexedDB.

## Автоматические проверки

Актуальный расширенный прогон: [GitHub Actions run #40910384996](https://github.com/Glupozombie/life-engine/actions/runs/40910384996) — **SUCCESS**. На Node.js v22.23.4 прошли синтаксическая проверка 6 JS-файлов в `js/`, `tests/` и `scripts/`, **13/13 тестов**, сравнительный эксперимент среды на 12 поколений, проверка целостности ZIP и синтаксиса 4 JS-файлов внутри архива.

Эксперимент при одном seed показал: популяция 72 → 126 в balanced, 72 → 175 в abundance и 72 → 75 в scarcity. Это предварительное наблюдение одного детерминированного прогона, не доказательство универсального закона. Подробности и средние признаки по поколениям — в `docs/TESTING.md`.

Автотесты проверяют чистую логику, включая наследование/ограничение мутации, энергозатраты признаков, получение энергии от пищи и повторяемость эксперимента. Они не заменяют браузерный E2E и не подтверждают реальное сохранение в IndexedDB.

## Следующие приоритеты

1. Повторить эксперимент на нескольких seed и большем числе поколений; проверить, какие изменения средних признаков устойчивы, а какие являются случайным дрейфом.
2. Добавить отдельную причинную проверку стоимости размножения и соответствия записей журнала реальным событиям.
3. Провести браузерный smoke-тест и отдельно подтвердить IndexedDB, слоты, перезапуск и экспорт/импорт. Пользователь сообщил, что заметных багов не увидел, но независимого E2E-прогона ещё нет.
4. Проверить вымирание, исчерпание ресурсов, лимиты популяции и длительный ускоренный прогон.
5. Измерить FPS и проверить память при большой популяции.
