# Проверки и контроль качества

> На момент создания документа команды проекта не подтверждены. Не запускай команды наугад, сначала прочитай фактические конфигурационные файлы.

## Первый аудит
- [ ] Осмотреть дерево репозитория и скрытые конфигурационные файлы.
- [ ] Найти инструкции по установке и запуску.
- [ ] Определить команды lint, typecheck, test и build, если они существуют.
- [ ] Установить проект по инструкциям и выполнить production-сборку.
- [ ] Запустить приложение и проверить консоль браузера.
- [ ] Зафиксировать результаты, версии окружения и известные ошибки.

## Сценарии симуляции
- [ ] Мир запускается, ставится на паузу и корректно меняет скорость.
- [ ] Организмы двигаются и взаимодействуют со средой.
- [ ] Потребление ресурсов меняет состояние организма/ресурс среды согласно правилам.
- [ ] Размножение создаёт потомков и сохраняет происхождение.
- [ ] Признаки наследуются; мутации происходят в предусмотренных моделью пределах.
- [ ] Разные признаки дают проверяемые различия в поведении или выживании.
- [ ] Смерть удаляет особь из активной симуляции и корректно отражается в истории.
- [ ] Нулевая популяция не ломает UI и симуляцию.
- [ ] История событий и дерево происхождения согласованы с реальными событиями.

## Сохранения
- [ ] Сохранение и загрузка восстанавливают состояние мира.
- [ ] После перезапуска браузера сохранение остаётся доступным.
- [ ] Повреждённое или несовместимое сохранение обрабатывается без бесконтрольного падения.
- [ ] Экспорт и импорт, если реализованы, проходят круговой тест.
- [ ] Офлайн-прогресс, если реализован, ограничен и соответствует правилам модели.

## Производительность
- [ ] Проверить обычную численность популяции.
- [ ] Проверить высокую численность.
- [ ] Проверить ускоренный режим и длительную работу.
- [ ] Проверить, что история и объекты не растут бесконтрольно.
- [ ] Зафиксировать ориентировочные показатели FPS/времени шага и условия теста, если возможно.

## Формат отчёта
Для каждого прогона записывать дату, окружение, команду/сценарий, результат (PASS/FAIL/BLOCKED), наблюдения и связанные ошибки. Не обозначать ручную проверку как автоматический тест.
